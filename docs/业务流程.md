# ShopHelper 的业务流程

## 查订单和物流

用户发送订单卡片，或者直接输入订单号。助手调用电商接口读取数据，再回答订单和物流状态。会话会记住当前订单，方便继续追问。

## 申请退款

1. 收集订单号和退款原因。
2. 检查演示用户是否拥有该订单、订单状态是否支持申请，以及是否已有进行中的申请。
3. 展示订单和原因。用户可以修改原因，也可以取消。
4. 用户明确回复“确认提交”后，才创建退款申请。待确认内容 10 分钟后过期。
5. 成功时返回数据库中的申请编号，并说明正在等待审核。
6. 用户继续问“退款成功了吗”，就读取当前订单的退款记录。

同一笔申请重试时使用相同编号。业务服务在处理同一订单时加锁，并检查已有申请，避免重复创建。接口超时意味着结果暂时无法确认，应先查询进度，不能直接回复成功。

“新对话”会结束当前对话流程和待确认内容，但不会删除聊天历史，也不会撤销已经提交的退款申请。

## 现在还没做的部分

正式账号登录、后台审批、支付退款和资金对账还没有接入。演示中的可申请订单状态是项目自己的示例规则，不等同于任何电商平台的正式政策。

当前同用户消息的串行处理只在单个客服进程内生效。以后部署多个进程，需要补充跨进程的并发控制。
